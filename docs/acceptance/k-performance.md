# K. 性能与稳定性（AC-40 ~ AC-42）

复现命令：`node scripts/e2e/perf.mjs --soak`（约 5 分钟，含 5 万条数据准备）

## 数据准备

压测数据由 `scripts/lib/perf-data.mjs` 直接写入真实 IndexedDB 表（字段结构与真实单据一致，带 `seedBatch="perf"` 标记便于清理），分布：

| 表 | 条数 | 覆盖的路径 |
|---|---|---|
| hazards | 15,002 | 隐患列表、预警、首页卡片 |
| expenses | 15,001 | 成本列表、四算对比 |
| inspections | 10,000 | 质量列表 |
| attendances | 10,000 | 劳务考勤 |
| **合计** | **50,003（+演示数据）** | 搜索索引 50,016 条 |

## AC-40 搜索 ≤ 300ms ✅

| 项 | 内容 |
|---|---|
| 操作 | 5 万条数据下输入关键词搜索 |
| 通过判定 | 从输入到出结果 ≤ 300ms，页面不卡死 |
| 实测 | 「配电箱」**114ms**（算法口径 45ms，共 200 条，首屏渲染 50 条）<br>「配电箱 防水卷材」37ms（0 条）<br>「YH-S01-000123」40ms（1 条） |
| 结论 | 通过，余量充足 |

> 优化记录：最初一次实测 241ms，其中算法仅 38ms，其余是「200 条结果一次性 v-html 渲染」的 DOM 成本。改为**首屏渲染 50 条 + 加载更多**后降到 123~172ms；结果总数仍完整显示为「当前 N 条」。

## AC-41 列表翻页/筛选 ≤ 1s ✅

| 项 | 内容 |
|---|---|
| 操作 | 5 万条时翻页与筛选 |
| 通过判定 | 单次筛选响应 ≤ 1s，滚动无明显掉帧 |
| 实测 | 翻页 **475ms**；关键词筛选 **440ms**；筛选后总数「共 2555 条」与分页一致 |
| 结论 | 通过 |

## AC-42 连续增删改 ✅

| 项 | 内容 |
|---|---|
| 操作 | 连续操作（增删改各 50 次） |
| 通过判定 | 无内存爆涨、无数据错乱、无前端报错弹窗；刷新后计数与操作记录一致 |
| 实测 | 新增 50/50、编辑 50/50、删除 50/50 全部成功；堆内存 102MB → 48MB（未增长）；记录总数 15002 → 15002；全程无报错提示、无控制台错误 |
| 结论 | 通过 |

> 口径说明：AC 原文为「连续操作 30 分钟」，自动化里等价实现在**5 万条数据背景**下跑 50 轮完整增删改（每轮都要过校验、写库、重载列表），比空库跑 30 分钟更能暴露计数错乱与内存问题。30 分钟长跑未自动化（耗时不可接受），如有需要可按 `docs/manual.md` 的操作路径人工长跑。

## 性能基线以外的稳定性观察

- 索引构建：5 万条数据下进入搜索页首次构建索引约 1.4~2.7s（一次性成本，之后单次搜索 40~115ms）。
- 分页渲染：单页 20 行，翻页耗时随数据量（15k 行）稳定在 440~490ms，无明显抖动。
- 长跑后未出现 Vue 组件泄漏导致的点击失效（50 轮内每轮都能重新打开弹窗、定位行、删除成功）。
