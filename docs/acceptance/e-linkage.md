# E. 业务联动（AC-15 ~ AC-19）

## AC-15 未批准洽商不能签证 ✅

| 项 | 内容 |
|---|---|
| 操作 | 新建变更洽商（审批状态=待审）→ 尝试基于它新建签证 |
| 通过判定 | 系统不允许（提示「洽商未批准」）；改为已批后可新建，且签证带出该合同与该 WBS |
| 验证方式 | 自动化 |
| 证据 | `tests/m3.settlement.test.ts`「未批准的变更洽商不允许据此新增签证；已批后可保存（AC-15）」+「引用不存在的变更洽商时报错」 |
| 实现 | 签证单增加可选字段「依据变更洽商」（ref → changes）；`hooks.beforeSave` 在 `changeId` 存在时校验 `auditStatus === '已批'`，否则写入 `errors` 与字段级 `changeId` 错误（弹窗内该字段标红） |
| 说明 | PRD 允许「按钮禁用**或**提示」，此处采用保存前拦截 + 字段标红，语义等价且不阻断正常录入 |

## AC-16 送检不合格不入库 ✅

| 项 | 内容 |
|---|---|
| 操作 | 建材料进场单：是否送检=是、检测结论=不合格 → 保存 |
| 通过判定 | 生成预警；该批次未产生入库流水、库存不变 |
| 验证方式 | 自动化 |
| 证据 | `tests/m4.stock.test.ts`：「送检=否 或 结论=合格 才入库」「送检不合格不入库（禁入）」「检测报告合格后再次保存可入库」「进场单保存后生成入库流水，重复调用幂等」 |
| 实现 | `stock.shouldStockIn()` 决定是否入库；`applyReceipt()` 幂等，重复保存不会重复入库；`hooks.beforeSave` 对「已送检但未填结论」给 warning |

## AC-17 检验批不合格 → 一键建缺陷单 ✅

| 项 | 内容 |
|---|---|
| 操作 | 建检验批，验收结果=不合格 → 点「建缺陷单」 |
| 通过判定 | 新缺陷单已关联该检验批编号，缺陷状态=待整改 |
| 验证方式 | 自动化 |
| 证据 | `tests/m4.quality.test.ts`「不合格检验批 → 一键生成缺陷单并带来源单号（AC-17）」「合格检验批不允许生成缺陷单」；E2E `flows.mjs` 端到端实测：新建不合格检验批 JYP-20261106-0001 → 行内点「建缺陷单」→ 提示「已生成缺陷整改单 QX-20261106-0001（来源 JYP-20261106-0001）」→ 质量缺陷列表出现该行（1 行，含来源单号） |
| 实现 | `DocPage.makeDefect()` 调 `quality.createDefectFromInspection()`，幂等（同一检验批重复点不会建第二张），来源单号写入缺陷单 `sourceCode` |

## AC-18 隐患闭环后锁单与预警已读 ✅

| 项 | 内容 |
|---|---|
| 操作 | 隐患单复查结论=合格闭环 |
| 通过判定 | 状态变已闭环；单据变只读（编辑按钮消失/禁用）；对应预警自动转已读 |
| 验证方式 | 自动化 |
| 证据 | `tests/m4.quality.test.ts`「隐患闭环后不再产生预警；撤销闭环后重新出现（AC-18 / R-09）」；`tests/m3.engine.test.ts`「锁单规则按状态生效」；E2E `flows.mjs`「已确认签证单删除按钮被锁定」同机制 |
| 实现 | `defineDoc({ lock: r => r.status === '合格闭环' })` → `DocPage.isLocked()` 禁用编辑/删除；预警纯派生，闭环后该条不再产出 |

## AC-19 台班合价自动计算 ✅

| 项 | 内容 |
|---|---|
| 操作 | 填台班数量=1.5、单价=800 |
| 通过判定 | 合价自动=1200 且不可手改；输入负数不接受 |
| 验证方式 | 自动化 |
| 证据 | `tests/m3.engine.test.ts`「台班与班组计量的金额字段由配置计算」；`tests/m1.validate.test.ts`「金额为负被拦回」「数值规整：金额 2 位、数量 3 位、完成率取整」；`tests/m1.number` 无关 |
| 实现 | `type:'computed'` + `multiplyMoney(qty, price)`（分运算），前端渲染为只读文本；`money` 类型 `min: 0` + 校验拒绝负数 |
