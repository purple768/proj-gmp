# J. 备份与恢复（AC-35 ~ AC-39）

## AC-35 导出备份包结构 ✅

| 项 | 内容 |
|---|---|
| 操作 | 点【导出整包备份】 |
| 通过判定 | 展示「共 N 条记录、M 个附件、合计大小」；得到 zip；解压可见 manifest.json、data/、files/ 三部分，附件数与系统内一致 |
| 验证方式 | 自动化 |
| 证据 | `tests/m5.backup.test.ts`「导出包含 manifest、数据表与附件字节」「导出可中断/流式：回调收到进度」；`flows.mjs`「备份导出生成 zip」实测落盘 `工程管理备份_2026-11-06.zip` |
| 结构 | `manifest.json`（版本/时间/行数/附件数/字节）、`data/<table>.json`、`files/<hash>.<ext>` |

## AC-36 空库导入恢复 ✅

| 项 | 内容 |
|---|---|
| 操作 | 清空全部数据后导入备份包 |
| 通过判定 | 项目、WBS、全部单据、附件全部恢复；抽查 3 张单据字段与照片可打开 |
| 验证方式 | 自动化 |
| 证据 | `tests/m5.backup.test.ts`「导出的包能完整导入空库，数据与附件一致」（含附件字节比对）；`flows.mjs` 导出后 zip 存在且可被解析 |
| 手工补充 | 恢复后抽查附件是否能预览（依赖浏览器查看器，见 AC-09） |

## AC-37 冲突三策略 ✅

| 项 | 内容 |
|---|---|
| 操作 | 已有同编号项目时再导入，分别选跳过/覆盖/另存 |
| 通过判定 | 每条可选策略；选「跳过」后原数据未被改动 |
| 验证方式 | 自动化 |
| 证据 | `tests/m5.backup.test.ts`「冲突策略 skip：不新增也不覆盖」「冲突策略 overwrite：保留本地 id 覆盖内容」「冲突策略 rename：编号加 -R1，且子节点与单据引用一并迁移（R-08）」 |
| 实现 | `importBackup(bytes, policy)`；rename 时 `withSuffix()` 生成 `-R1`，并同步迁移 WBS `parentId`、单据 `projectId` 引用 |

## AC-38 清空后整体恢复 🟡

| 项 | 内容 |
|---|---|
| 操作 | 设置页点【清空后整体恢复】选备份包 |
| 通过判定 | 出现红色二次确认；确认后数据恰为备份包内容，无残留旧项目 |
| 验证方式 | 半自动 |
| 证据 | `views/settings/index.vue#onRestoreAll()`：先 `type:'error'` 红色确认「会先删除本机全部项目、单据与附件」，再二次确认「本机现有数据将被完全替换」；确认后 `clearAllData(false)` → `importBackup(buf,'overwrite')` → 刷新 |
| 需目视 | 两次红色弹窗的样式与文案；恢复后项目列表只剩备份内项目 |
| 手工步骤 | 导出备份 → 新建一个明显不同的项目 → 清空后整体恢复 → 确认新项目消失、备份内容回来 |

## AC-39 恢复中途强制关闭 ⚪

| 项 | 内容 |
|---|---|
| 操作 | 恢复过程中强制关闭页面 |
| 通过判定 | 再次打开时数据仍为操作前状态（无半截数据、无孤儿附件） |
| 验证方式 | 手工（已明确设计取舍） |
| 现状说明 | **导入不是原子操作**：按表逐张写入，中途关闭可能留下「已导入的表 + 未导入的表」。这一点在 `docs/adr/004` 与 `docs/manual.md` 中已写明，规避手段是「导入前先导出一份当前数据」。 |
| 为什么不加事务 | IndexedDB 单事务跨 41 张表写 GB 级附件会让浏览器长时间锁库甚至崩溃；`fflate` 流式导入与事务内全量写入不兼容 |
| 手工步骤 | 用一个大备份包导入 → 中途关标签页 → 重开 → 检查项目数与附件是否成对（不出现只导入一半且无法识别的孤儿数据） |
| 建议 | 若必须强一致，需要引入「导入到临时库 + 校验通过后整体切换库名」的两阶段方案（已在架构文档 §11 列为后续项） |
