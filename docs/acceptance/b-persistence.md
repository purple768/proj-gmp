# B. 数据持久化（AC-06 ~ AC-08）

## AC-07 关闭浏览器再打开 ⚪

| 项 | 内容 |
|---|---|
| 操作 | 完全关闭浏览器 → 重新打开应用 |
| 通过判定 | 数据全部还在；若数据目录需重新授权，出现明确引导提示（而非数据丢失） |
| 验证方式 | 手工 |
| 为什么不能自动 | E2E 使用无头浏览器的临时用户目录，进程退出即丢弃 profile，无法复现「关掉再开」 |
| 手工步骤 | 1) `npm run dev`，新增 1 条隐患单；2) 完全退出浏览器（结束所有窗口）；3) 重新打开 `http://127.0.0.1:3100`；4) 确认该隐患单仍在；5) 若顶部出现「数据目录尚未授权」横幅，点「重新授权」后确认附件仍可打开 |
| 已具备的支撑 | 数据存 IndexedDB（随 profile 持久）；`initStorage()` 启动时读回目录句柄并 `queryPermission`，失权时降级 + 顶部横幅引导（`layout/index.vue`） |

## AC-08 500MB 以上文件 ⚪

| 项 | 内容 |
|---|---|
| 操作 | 上传 1 个 500MB 以上文件（PDF/IFC） |
| 通过判定 | 上传成功无报错、不触发大小限制提示；设置页能看到该文件已计入占用 |
| 验证方式 | 手工（代码层已确认无大小限制） |
| 代码证据 | 上传链路 `DocPage.onPickFiles → addAttachment → writeBytes` 全程没有 `file.size` 上限判断；`checkQuota` 只在「已用 ≥95% 且单文件 >10MB」时拦截，正常容量下不拦 |
| 自动化替代 | `tests/m1.attachment.test.ts`「写入 3MB 文件后可读回，字节数一致」验证大 Blob 分片写入与读回 |
| 手工步骤 | 1) 设置页选一个本地文件夹；2) 打开任一单据，附件区传 500MB 文件；3) 观察进度与结果提示；4) 到设置页看「附件占用」是否增加约 500MB |
| 风险提示 | 目录模式（File System Access）最适合大文件；OPFS/IndexedDB 模式受浏览器配额约束，可能触发容量提示（属预期行为） |
