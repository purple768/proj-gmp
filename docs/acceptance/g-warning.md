# G. 预警体系（AC-25 ~ AC-27）

## AC-25 优先级分级与排序 ✅

| 项 | 内容 |
|---|---|
| 操作 | 建 1 张重大隐患、1 张一般隐患 |
| 通过判定 | 预警汇总出现 2 条，优先级分别紧急/一般，紧急在前（或可排序） |
| 验证方式 | 自动化 |
| 证据 | `tests/m5.warning.test.ts`「紧急/一般分级：重大隐患或逾期为紧急」；预警页表格支持按优先级排序，「紧急」默认排前 |
| 实现 | `computeWarnings()` 输出 `priority: '紧急' | '一般'`，重大隐患/已逾期 → 紧急 |

## AC-26 证件到期判定 ✅

| 项 | 内容 |
|---|---|
| 操作 | 特种证件有效期=今天+20 天；再改成今天−5 天 |
| 通过判定 | 剩余天数=20、状态「即将到期」、预警「一般」；改后变「已过期」+ 紧急 |
| 验证方式 | 自动化 |
| 证据 | `tests/m4.quality.test.ts`「证件剩余天数按自然日，且分三档状态（AC-26 / R-13）」「证件到期在预警中分级：过期紧急、30 天内一般」 |
| 实现 | `remainDays()` 用日历日差；`expireStatus()` 三档：正常 / 即将到期（≤30 天）/ 已过期 |

## AC-27 预警打开来源单据 ✅

| 项 | 内容 |
|---|---|
| 操作 | 点击某条预警的「来源单据」 |
| 通过判定 | 正确跳转到产生它的那张单据详情 |
| 验证方式 | 自动化 |
| 证据 | `flows.mjs`「预警可打开来源单据」实测抽屉内容 `来源单据 YH-20261106-0001 预警类型 安全隐患 优先级 紧急` |
| 实现 | 预警携带 `docType + docId + sourceCode`，抽屉内渲染该单据字段快照并提供跳转 |
