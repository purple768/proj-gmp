# ADR-002 单据配置化：一份 `defineDoc` 驱动全部 UI

- 状态：已采纳
- 日期：2026-11-06

## 背景

PRD 要求第一版覆盖 32 类业务单据，字段 6~15 个不等，但**交互高度同构**：列表 + 筛选 + 新增/编辑弹窗 + 详情 + 打印 + 导出 + 进搜索索引。

## 决策

不手写 32 套页面，改为「配置 + 一个通用页面」：

- `src/core/docs/*.ts` 里用 `defineDoc()` 声明字段、锁单规则、打印模板、日期/状态字段、搜索字段；
- `src/components/DocPage.vue` 读配置渲染列表、筛选、表单、校验错误、计算字段、附件上传、打印/导出；
- 引擎层（`core/engine/validate.ts`）统一做必填/数值范围/枚举校验、默认值、计算字段、数值规范化（金额 2 位、数量 3 位、百分比取整）。

## 理由

- 32 类单据的配置约 1000 行；若手写页面约 2.5 万行，且改一处交互要改 32 遍。
- 一致性：所有单据的分页、筛选、错误提示、打印行为天然相同，验收时不必逐页挑差异。
- 新增单据成本降到「加一个配置文件 + 在 `index.ts` 注册」。

## 代价

- 个别单据的定制交互（检验批「建缺陷单」、工资「按已审核计量取数」）需要在 `DocPage.vue` 里按 `cfg.key` 打补丁——目前 2 处，可接受。
- 配置里的 `computed` 是函数，无法序列化，因此备份包里不存配置，只存数据（配置跟着代码走）。
