# ADR-001 用 Dexie/IndexedDB 作为唯一持久层，不引入后端

- 状态：已采纳
- 日期：2026-11-06

## 背景

需求是「单机、离线、一个人用、数据不出本机」。候选方案：IndexedDB 直连、SQLite（WASM）、本地文件 JSON、Electron + 本地数据库。

## 决策

用 Dexie 4 封装 IndexedDB，作为唯一持久层；附件字节另存文件系统（见 ADR-003）。

## 理由

- **零部署**：静态站点直接跑，不需要装 Node/服务/数据库，符合「打开即用」。
- **事务与索引**：Dexie 提供事务、复合索引、批量读写，41 张表的查询条件（项目 + 编号、项目 + WBS 等）都能走索引。
- **容量**：Chrome/Edge 下单个 origin 可到配额上限（通常为磁盘可用空间的 60%），远超「几百个项目」的量级。
- **可测试**：`fake-indexeddb` 让 `core` 层能在 Node 里跑单元测试，不必开浏览器。

## 代价

- 数据绑在浏览器 profile 上：清浏览器数据即清库 → 用「备份包」作为唯一的迁移/保险手段（ADR-004），并在设置页明确提示。
- 没有 SQL 的聚合能力：统计都在 JS 里算 → 靠分页 + 索引控制数据量，5 万条量级可接受。
- `SQLite WASM` 在持久性（需要 OPFS 且写放大）与生态成熟度上不如 IndexedDB，且调试工具少。
