# ADR-007 软删除 + 90 天回收站，附件字节随「永久删除」才释放

- 状态：已采纳
- 日期：2026-11-06

## 背景

误删单据在工程现场是高频事故；但附件字节体积大，不能在回收站里长期堆着。

## 决策

- 业务表统一用 `deletedAt` 做软删除，列表默认过滤 `deletedAt == null`，回收站只查非空。
- 回收站保留 **90 天**（`KEEP_DAYS`），启动时 `cleanupExpired()` 清理到期记录；剩余 ≤7 天在回收站页高亮提示。
- 附件在单据软删除时只置 `pending-trash`，**不释放字节**；恢复时回 `active`；永久删除 / 到期清理时才 `releaseAttachment()` 减引用并删字节。
- 恢复时若编号已被新单据占用，自动改名为 `-R1`（`restoreDoc_`），避免恢复失败。

## 理由

- 恢复必须是「原样回来」，包括能点开附件，所以字节不能提前删。
- 90 天是造价/监理资料常见的追溯窗口，足够发现误删。

## 代价

- 回收站会暂时占用双份空间（删了但字节还在）→ 设置页的配额提示要把 `pending-trash` 也算进去。
- `deletedAt` 不在索引里（`projects/wbs` 有，其他表没有）→ 回收站查询是遍历非空判断，5 万条量级下约 100ms，可接受；不做额外索引以省写入成本。
