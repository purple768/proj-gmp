# ADR-006 金额用「分」运算，日期用日历日差

- 状态：已采纳
- 日期：2026-11-06

## 背景

工程结算对金额与日期极其敏感：`0.1+0.2` 的浮点误差在累加几百行后会变成可见的「差一分」；`(end-start)/86400000` 在跨夏令时/带时区时间戳下会算出 4.958 天这类结果。

## 决策

- 金额：存储仍是「元」的两位小数（人对人友好、Excel 直接可读），但**任何运算先 `toCents()` 转整数分，算完 `fromCents()` 回元**。典型：`multiplyMoney(qty, price) = fromCents(round(qty * toCents(price)))`。
- 日期：一切比较先 `dateOnly(ts)` 归一到当天 0 点，再用 `dayDiff(a, b)` 求**日历日差**（`Math.round` 毫秒差 / 86400000，且两侧都已归零）。区间筛选的右端统一 `setHours(23,59,59,999)`，保证「含首尾日」。

## 理由

- 分是整数，`Number.MAX_SAFE_INTEGER` 下可安全表示约 90 万亿元，工程金额远不会溢出。
- 日历日差符合业务口径：「限期 3 天」就是 3 个自然日，和时区、夏令时无关。

## 代价

- 每处计算都要记得转分，靠 `tests/m6.date.test.ts`、`tests/m3.*` 兜住；直接 `a*b` 的写法在 code review 时要拦住。
- 精度固定 2 位：单价超过 2 位小数（如 3.125 元/方）会按分取整，符合造价习惯。
